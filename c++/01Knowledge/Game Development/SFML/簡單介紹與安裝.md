- 分工大概是這樣
	- c++編寫遊戲規則、物件行為與遊戲迴圈
	- G++真正負責編譯 C++ 程式
	- CMake工程的規劃者，描述原始碼、依賴套件與建置目標之間的關係，並產生建置工具需要的設定
	- 建置工具(Make)按照建置規則安排編譯及連結工作
	- SFML提供視窗、輸入事件、圖形繪製、音訊等遊戲開發功能，讓我們不用自己從作業系統底層開始實作
- 為了方便整理我把.cpp都放在一個叫src資料夾
- include資料夾放標頭檔
- 這裡不安裝在全域而是只有該專案，並透過CMakeLists.txt安裝
	- 這樣做第一次build要比較久，而且需要網路連線
	- 這是該github提到的方法[Github頁面](https://github.com/SFML/cmake-sfml-project/blob/master/CMakeLists.txt)
		- FetchContent_Declare告訴cmake從github取得專案
		- FetchContent_MakeAvailable(SFML)下載並將 SFML 加入build流程
		- target_link_libraries()將 SFML Graphics 模組連結到我們的遊戲程式
```

cmake_minimum_required(VERSION 3.28)

project(CppSandbox LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")

include(FetchContent)

FetchContent_Declare( 
    SFML
    GIT_REPOSITORY https://github.com/SFML/SFML.git
    GIT_TAG 3.1.0
    GIT_SHALLOW TRUE
)

FetchContent_MakeAvailable(SFML)

add_executable(CppSandbox
    src/main.cpp
)

target_link_libraries(CppSandbox PRIVATE SFML::Graphics)

```
