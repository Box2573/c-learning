## 傳值( pass by value)
- 直接把值傳進去並`複製一份`做使用
- 就像用影印機一出一份副本，怎麼塗鴉修改都不會影響到正本
- 可以看到因為是複製一份進去做使用，所以原始的a數值不會被改變
```c++
void add (int x)
{
    x += 100;
}

int main()
{
	int a = 0;
    add (a);
    std::cout << a << "\n";

    return 0;
}

//output: 0
```

## 傳址(pass by address)
- 傳入一個指標也就是位址因此是傳址
- 就像把地址給裝修師傅，要拿著鑰匙 * ，才可以打開修改裡面東西
- 需要用 * 解址
- 可以看到因為是傳入a的位址，因此可以看成她修改了a
```c++
void add (int *x)
{
    *x += 100;
}

int main()
{
	int a = 0;
    add (&a);
    std::cout << a << "\n";

    return 0;
}

//output: 100
```

## 傳參考 (pass by reference)
- 傳變數的別名(alias)做使用
- 修改了別名就等於修改了本尊
- 就像同個人只是我用綽號叫他
```c++
void add (int &x)
{
    x += 100;
}

int main()
{
	int a = 0;
    add (a);
    std::cout << a << "\n";
    
    return 0;
}

//output: 100
```

### 為什麼 `int& x` 不是取址
- &放在變數那邊就是取址
- &放在型態那邊就是宣告參考
- 可以用&放在等號哪邊來思考
```c++
int number = 10;

int* ptr = &number;  // &number：取出 number 的位址
int& ref = number;   // int&：宣告參考，讓 ref 成為 number 的別名
```

### 那為什麼要用傳參址不用傳參考就好
- 傳參考看起來的確比傳址方便但
	- 傳參考不能為NUll
		- 傳參考是綽號表示他一定要有這個人我才有辦法幫他取綽號(不可能幫一個不存在的人取綽號)，甚至用綽號叫他，所以`傳參考用法不能為null`
		- 傳址如果覺得沒東西可以傳空的位址`(nullptr)`進去，就像這個地址現在不存在未來可能蓋房子就有地址了
	- 不能更改綁定
		- 因為一個綽號對應一個人，因此`傳參考可以看成是唯一的沒辦法更改`
		- 傳只可以改，就像地址填錯了修改這樣
>[!warning] 可以這樣分辨什麼時候傳址什麼時候傳參考
>如果不一定要有，可以為空、隨時換對象->傳址
>一定要有不可以為空->傳參考
- 傳值可以和傳參考、傳址分為兩組比較
	- 先決定要用複製(值)的方法還是本尊(參考、址)
	- 為什麼需要確保你操作的是同一個本尊
		- 例如有個weapon被使用`Weapon myweapon`建立後，假設今天有可以提升武器傷害的系統要傳入要提升傷害的武器但你每次都這樣傳`void calculateDamage(Weapon w)`傳進去的都是一個新的武器結果背包的`myweapon`傷害都不變，因此要把本尊傳進去`Weapon& w`或`Weapon* w`

| **狀況**                                                 | **該用哪種宣告 / 傳遞？**                                     | **為什麼？**                    |
| ------------------------------------------------------ | ---------------------------------------------------- | --------------------------- |
| **只是個單純的數字**（如：血量 `int hp = 100`、速度 `float speed`）     | 直接宣告實體，傳遞時用**傳值**。                                   | 因為它很小，複製不費力，且各自獨立不會互相干擾。    |
| **一個複雜的自定義結構或物件**（如：`Weapon myWeapon`、`Player player`） | 在需要的地方宣告實體，但要傳遞給其他函數操作時，**絕對要用「傳參考 `&`」或「傳指標 `*`」**。 | 避免昂貴的記憶體複製開銷，並確保你操作的是同一個本尊。 |
