- 標頭檔就是宣告，例如我有什麼class什麼函式之類的，但你要在標頭檔實作其實也可以但通常標頭檔用來`主要描述類別提供什麼功能，而不是如何實現`
- .cpp也就是實作，專門去定義或實作函式裡的邏輯那些的
- 可以這樣判斷是否需要拆出.h->如果有個東西需要知道某個class的完整定義那可以拆出.h
	- 除了當前這個檔案，未來有沒有其他模組也會需要用到這份規格有可以拆成.h
	- 例如Cat雖然繼承自Pet但我有建立出cat這個物件了(:make_unique< Cat >("Mimi"))->需要知道完整宣告了才可以用她的建構子那些的
	- 如果今天只我透過Pet操控Cat那我可以不用建立cat.h因為完全不需要知道cat的完整定義
		- factory pattern可以這樣做
			- factory.h宣告一個create物件方法->cat.cpp去實作並回傳轉形成Pet->再透過Pet操控
> [!info] 通常判斷方法
> 當你把某個class放到main.cpp外面那要讓main.cpp知道該class長怎樣就需要.hpp，至於要不要有.cpp就看自己怎麼決定可以選擇不讓標頭檔有太多複雜實作選擇封裝與隱藏細節因此新增.cpp，但如果實作極短，可以選擇直接寫在.h稱為Inline 函式(如果實作真的太短再去開個.cpp可能管理上不方便)

>[!warning] 但有例外
>模板類別[[Template模板]]編譯時需要直接看到他是怎麼做的如果寫在.cpp她編譯時會找不到

- 標頭檔有兩種兩種功能一致
	- .h
		- 從c延續過來
	- .hpp
		- 專門用在c++(pp = plus plus)
		- 純 C++ 的標頭檔
- 寫標頭檔時可以用`#pragma once`
	- 確保該標頭檔在編譯時只會被引用(include)一次，例如
		- 有三個檔案，關係如下
			- `Weapon.h`（定義了武器類別）
			- `Player.h`（需要用到武器，所以 `#include "Weapon.h"`）
			- `main.cpp`（既需要玩家，也需要武器，所以同時 `#include "Player.h"` 和 `#include "Weapon.h"`）
			- 但今天`Weapon.h`被引入兩次會變成重複定義。用`#pragma once`時看到一樣的東西被include兩次他就會跳過

```c++
//pet.cpp
#include"Pet.h"//自己寫的通常用""include，但<>也可以

Pet::Pet(std::string petName): //建構子
    name(petName)//我已經告知這是Pet的建構子所以他知道有name的存在了
    {}

void Pet::decreaseHungry(int value)
{
     if(hungry - value <= 0)
    {
        hungry = 0;//我已經告知這是Pet的函式所以他知道有hungry的存在了因此不用Pet::hungry
    }
    else
    {
        hungry -= value;
    }
}

int Pet::getHungry() const
{
    return hungry;
}

std::string Pet::getName() const
{
    return name;
}
```

- petManager.cpp
```c++
#include "PetManager.h"
#include <limits>
#include <iostream>

void PetManager::showPetList()
{
    for(std::size_t i = 0; i < pets.size(); i++)
    {
        std::cout << i << ". " << pets[i] -> getPetType() << " " << pets[i] -> getName() << " 目前飢餓值: " <<  pets[i] -> getHungry() << "\n";
    }

    std::cout << "請輸入餵食哪一隻動物: "<< "\n";
}

 int PetManager::readPetID()
{
    int petID;

    showPetList();

    while (true)
    {
        std::cin >> petID;

        if(std::cin && petID >= 0 && static_cast<size_t>(petID) < pets.size())//如果輸入型態正確、範圍正常
        {
            break;//跳出迴圈
        }

        //如果失敗
        std::cout<<"輸入無效！請重新輸入一個數字: \n";
        showPetList();
        std::cin.clear();
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    }
    
    return petID;
}

void PetManager::addPet(std::unique_ptr<Pet> pet)
{
    pets.push_back(std::move(pet));//所有權現在在pet上要放到vector只能用move
}

void PetManager::getpetStatus() const
{
    for(const auto &pet : pets)
    {
        std::cout << "寵物名稱: " << pet -> getName() <<" 飢餓值:  " << pet -> getHungry() << "\n"; 
    }
}

void PetManager::feedPets()
{
    int petId;

    if(pets.empty())//先判斷vector是否為空
    {
        std::cout << "目前沒動物\n";
        return;
    }
    
    petId = readPetID();
    pets[petId] -> eat();
    std::cout <<"已餵食: " << pets[petId] -> getPetType() << " " << pets[petId] -> getName() << "\n";
}
```

## 多個檔案編譯
- 可以用g++編譯
	- `-std=c++17`：使用 C++17 標準。
	- `-Wall -Wextra`：開啟一組常見警告，幫助我們發現潛在問題。
		- 例如她出現`petID < pets.size()comparison of integer expressions of different signedness`意思是我們這裡用有號整數去跟無號整數比較有可能會有問題，可用[[使用static_cast轉變型態]]處理把int轉為`size_t無號整數`
	-  `main.cpp` `Pet.cpp` `Cat.cpp` `Dog.cpp`` PetManager.cpp`所有cpp一起編譯成一個exe
	- `-o pet.exe`：指定產生的執行檔名稱
```
g++ -std=c++17 -Wall -Wextra main.cpp Pet.cpp Cat.cpp Dog.cpp PetManager.cpp -o pet.exe
```
## 那他們如何運作的
- 探討為什麼我們只在main.cpp引入.h而.h只是宣告那些函式等東西卻可以執行，因為實際執行的東西不是放在.cpp嗎
	- 以main.cpp執行的petManager.feedPets();來說他會知道
		- feedPets是PetManager成員
		- 不回傳j東西，也不需要參數傳入
		- 這裡只是宣告，他不會知道實作在哪
		- 編譯後會產生一個呼叫這個函數所需的機器碼(鎖孔)
	- 但我們編譯時，編譯了所有cpp因此
		- 在編譯petManager.cpp的feedPets時會對應的符號(鑰匙)
		- 透過連結器連結鑰匙跟鎖孔所以可以執行
	- 而.h檔案不用編譯，因為他會把.h的東西貼在.cpp上方
	- 所以當今天有兩個cpp都定義了一樣的函式例如都定義了feedPets會產生
		- multiple definition（重複定義） 的連結錯誤
### 我們來觀察她實際運作的樣子
- 我們一樣用g++編譯但這次只編譯不連結，加入`-c`表示我只編譯
```c++
g++ -std=c++17 -c main.cpp
g++ -std=c++17 -c petManager.cpp
```
- 可以看到產生了`main.o` `petManager.o`
	- .o是目標檔，裡面有一些機器需要的二進位檔案，把程式換成處理器能執行的指令
- 用`nm`去執行.o檔
	- .o是二進位檔案，直接打開看不懂
	- nm可以列出目標檔案或執行檔中的符號
	- 加入`-C` nm會嘗試把他輸出成比較好閱讀的樣子
```c++
nm main.o
nm PetManager.o
nm -C main.o
nm -C PetManager.o
```
- `main.o` 中的呼叫端會顯示它需要的符號，通常標記為 `U`（未定義）
- `petManager.o` 中會顯示它提供的函數定義，通常標記為 `T`（位於程式碼區段）
- 要連結起來可以用
```c++
g++ main.o petManager.o pet.o cat.o dog.o -o pet.exe
```
- 如果想看到標頭檔怎麼串在cpp可以用
	- `-E` 表示只執行預處理，不進行一般的編譯
	- 用vscode打開.i可以看到怎麼main其實很龐大
```c++
g++ -std=c++17 -E main.cpp -o main.i
```
