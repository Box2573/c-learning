## 建立物件
- 通常有三種方式
1. 一般區域物件
	- 通常只做用在區域內
	- 超出範圍會自己刪除，不需手動delete
```
Cat myCat("Mimi");
```
2. 用new動態建立
	- 回傳指標因此要用指標接收
	- 要確定用delete釋放，否則可能有記憶體洩漏問題
```c++
Cat* myCat = new Cat("Mimi");
```
3. 使用智慧指標管理動態物件
	- `make_unique` 會建立動態物件，並交給 `unique_ptr` 管理
	- 不用手動delete
```c++
auto myCat = std::make_unique<Cat>("Mimi");
```
## 智慧指標
- 最直觀功能就是他會在物件超出作用範圍時刪除或觸發解構子
- 通常只有`new`出來的物件是我們要自己手動刪除的，其他他們通常會在超出作用範圍(遇到})觸發解構子
	- 這樣不用自己一直打delete甚至有時候忘了導致記憶體洩漏
	- 下面這樣寫就自己在生命週期結束前delete
	- 如果有多個return很有可能忘了delete
```c++
	int main()
	{
		Test *test = new Test();//new動態建立的物件必須指向指標
		if (條件)
		{
			delete test;
			return -1;
		}
		else if(條件)
		{
			delete test;
			return 1;
		}
	
		delete test;
		return 0;
	}
```
- 使用時要引入` #include<memory> `
- 主要有三種
	- `std::unique_ptr`:獨佔所有權，該所有權只屬於這個unique_ptr，不可被複製，只能透過 `std::move` 轉移所有權
		- 使用這個居多
		- 物件只有一個管理者使用或管理時可以用
		- 有兩種建立方式
			- `std::unique_ptr<T> p = std::make_unique<T>(args)`這裡不用打new但效果相當於 `new`
			- `std::unique_ptr<T> p(new args)`這裡要打`new`

	- `std::shared_ptr`:共享所有權，多個 `shared_ptr` 可以指向同一塊記憶體，內部有**參照計數（Reference Count）**。當計數歸零時才真正釋放資源
		- 多個物件或函式需要共用同一份資源時可使用
	- `std::weak_ptr`: 沒有所有權的觀察者，用來搭配 `shared_ptr` 只負責「觀察」資源是否存在
		- 解決 `shared_ptr` 互相參照導致的**循環參考

- 以下用`std::unique_ptr`示範整個生命週期及運作
```c++
#include<iostream>
#include<memory>//要用智慧指標要引入memory

class Test
{
    public:
        Test()
        {
            std::cout << "這裡是建構子[建立] Test 物件誕生了！\n";
        }

        ~Test()
        {
            std::cout << "這裡是解構子[解構] Test 被自動釋放了！\n";
        }

        void doSomething()
        {
            std::cout << "!!! 程式運作中 !!!\n";
        }

}; 

int main()
{
    std::cout << "--- 主程式開始 ---\n\n";
    //此用{}故意製造一個範圍
    {
      std::cout << "進入了大括號範圍內...\n";  
      std::unique_ptr<Test> ptr = std::make_unique<Test>();    
      //unique_ptr<Test> ptr:宣告一個獨佔擁有Test的智慧物件
      //make_unique<Test>():建立(new)Test物件並把他給智慧指標管理

        ptr -> doSomething();

      std::cout << "即將離開大括號範圍...\n";

    }//智慧指標在這個}後超出範圍觸發回收

    std::cout << "\n已經離開大括號範圍了!\n";
    std::cout << "--- 主程式結束 ---\n";

    return 0;
}
```

- 她當然也可以搭配vector
	- 此時如果要遍歷無法用unique_ptr< Pet > pets: petShop這種寫法因為unique是獨佔，無法被複製也就沒辦法複製給 pets，改用傳址&參考的話就不會觸發無法被複製的問題
```c++
int main ()
{
    std::vector<std::unique_ptr<Pet>> petShop;//有個叫petShop的vector用來存儲獨佔擁有Pet的智慧物件

    petShop.push_back(std::make_unique<Cat>("Mimi"));//cat和dog都是public繼承pe因此可以轉成pet
    petShop.push_back(std::make_unique<Dog>("Bobo"));

    for(const auto &pets : petShop)//傳參考用法，不會觸發unique無法被複製的問題
    {                              //採用auto讓他自己判斷變數型態最快 
                                   //const不寫其實也可以但我不希望在這裡動到pets因此讓他唯獨，這樣比較安全
        pets -> eat();
        std::cout << "寵物名稱: " << pets -> getName() <<" 飢餓值:  " << pets -> getHungry() << "\n"; 

    }

    return 0;
}
```
- 所有權無法複製只能用move轉移
```c++
int main()
{
	std::unique_ptr<Test> ptrA = std::make_unique<Test>();
	std::unique_ptr<Test> ptrB = std::move(ptrA);//所有權從A移到B這樣A就空(nullptr)了

	return 0;	
}
```
- make_unique< Cat >("Mimi")產生的是暫時物件可以直接轉移例如上面例子我們直接轉入了vector可以看成
	- 這隻貓我還沒命名(變數名稱)所以可以直接把所有權給 petShop讓make_unique接收
- 如果我已經命名變數了(這隻貓有名字了)那要轉移所有權只能用move了
```c++
int main()
{
	std::vector<std::unique_ptr<Pet>> petShop;

    petShop.push_back(std::make_unique<Cat>("Mimi"));//還沒命名是暫時物件所以可以直接轉移所有權
    
    auto dog = std::make_unique<Dog>("Bobo")
    petShop.push_back(std::move(dog));//已命名了只能用move轉移所有權

	return 0;	
}
```
